# Скажи мне, кто твой шлиф

Ссылка на рабочий проект: http://84.201.139.95:8501
Автоматическая классификация геолого-технологического сорта руды по снимку аншлифа
(отражённая оптическая микроскопия). Кейс Норникеля.

**На выходе:** вердикт о сорте (`ordinary` / `hard_to_process` / `talc`) от
классификатора, 🔵 синяя маска талька поверх снимка, доля талька `talc_pct`, строка
согласованности вердикта с %талька, текстовое заключение и PDF-отчёт.

> Скоуп по уточнениям жюри: сегментируем **только тальк** (разметка есть лишь по
> оталькованию — синие обводки). Срастания сульфидов не сегментируем. Разделение
> `ordinary` vs `hard_to_process` делает **только классификатор**. См. `TASKS.md`.

## Архитектура — два дополняющих трека

1. **Классификатор сорта** (`core/classifier.py`) — transfer learning
   (EfficientNet-B0 / ResNet50, ImageNet). Классифицирует изображение целиком →
   даёт **вердикт**.
2. **Сегментация талька** (`core/segment.py`) — классический CV. Даёт **маску талька
   и `talc_pct`** (срастания не сегментируем).

`core/analyze.py` объединяет их: вердикт от классификатора, тальк-маска и `talc_pct`
от сегментации; поле `consistency_check` показывает, сходится ли вердикт с долей
талька (не переопределяя классификатор). Без весов классификатора — fallback:
`talc_pct` > 10% → `talc`, иначе `ordinary`; сегментация талька работает сразу.

## P4: интерфейс и сдача

`app/main.py` — локальный Streamlit-интерфейс для демо:

- загрузка одного или нескольких снимков (`TIFF / PNG / JPEG / BMP`);
- кэшированный вызов `core.analyze()`, чтобы зум и экспертные правки не пересчитывали снимок;
- вердикт сорта, источник ответа и строка согласованности;
- синяя маска талька с перемещением мышью, зумом колесом и сбросом;
- блок экспертной проверки: подтвердить вердикт или исправить сорт, добавить комментарий;
- выгрузки: PDF-отчёт по снимку, JSON результата, JSON экспертной правки, общий CSV.

Материалы для сдачи:

- `docs/submission.md` — упаковка 4 ссылок: репозиторий / облако / презентация / деплой;
- `docs/demo_video_script.md` — сценарий короткого демо-видео;
- `docs/presentation_outline.md` — структура презентации;
- `docs/p4_interface_presentation.pptx` — презентация на 18 слайдов про P1/P2/P3/P4;
- `notebooks/P4_interface_report.ipynb` — подробный ноутбук по P4.

### Логика вердикта
- сорт (`ordinary` / `hard_to_process` / `talc`) определяет классификатор изображения;
- `talc_pct` > 10% — порог согласованности/fallback, а не правило через морфологию
  срастаний (их не считаем).

## Структура

```
core/segment.py      # нормализация → тальк-детектор → синяя маска + talc_pct; тайлинг; синие обводки
core/classifier.py   # обучение и инференс классификатора (сплит по ID шлифа)
core/analyze.py      # контракт analyze() — объединяет оба трека
core/labels.py       # маппинг папок ч1/ч2 в 3 канонических класса + извлечение ID шлифа
core/report.py       # текст-вердикт (RU), CSV, PDF
api/main.py          # FastAPI: upload → analyze() → JSON, batch, CSV, PDF
app/main.py          # Streamlit: загрузка, маска с зумом, метрики, вердикт, экспорт
docs/                # чек-лист сдачи, сценарий видео, презентация
notebooks/           # ноутбук P4 + эксперименты P1/P2
scripts/train.py     # запуск обучения
scripts/calibrate_talc.py    # P1: подбор TALC_* по синим обводкам
scripts/benchmark_tiling.py  # P1: проверка бюджета тайлинга панорам
config.py            # DATA_DIR, пути к весам, все пороги — в одном месте
Dockerfile           # CUDA 12.2 + проверка GPU
```

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# torch под CUDA на сервере:
# pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

# 1) API
uvicorn api.main:app --reload            # http://localhost:8000/docs
# 2) UI
streamlit run app/main.py                # http://localhost:8501
# 3) обучение классификатора
python scripts/train.py --epochs 15
```

Всё работает **сразу**: сегментация — на чистом CV, вердикт — rule-based, пока не
обучен классификатор. `ANALYZE_STUB=1` форсит заглушку (фейковые числа, пустая маска)
для параллельной разработки фронта/бэка.

Для проверки только интерфейса без OpenCV/torch:

```bash
ANALYZE_STUB=1 streamlit run app/main.py
```

Метка класса = имя папки. `ч1` и `ч2` используют разные написания одних и тех же
сортов — `core/labels.py` сводит их в 3 канонических класса
(`тонкие` = `Труднообогатимые руды` = `hard_to_process`).

## Контракт `analyze(image) -> dict`

```python
{
  "image_id": str,
  "verdict": "ordinary" | "hard_to_process" | "talc",   # от классификатора
  "talc_pct": float,                                     # от тальк-сегментации
  "talc_mask_png_b64": str,                              # синяя маска талька поверх снимка
  "consistency_check": str,                              # сходится ли вердикт с %талька (RU)
  "classifier_confidence": float | null,
  "processing_time_sec": float,
  # + verdict_source (доп.)
}
```

## Критичные правила (зашиты в код)

- Классификатор: сплит train/val **по ID шлифа** (`GroupShuffleSplit`), не по картинкам.
- Аугментации **обязательно** с `RandomGrayscale` + `ColorJitter` (снимки дико разные
  по цвету — иначе модель учит цвет, а не минералогию).
- Дисбаланс: class weights (обратно пропорц.) + oversampling оталькованных.
- Метрики: macro-F1 + confusion matrix.
- Сегментация талька: **сначала** per-image нормализация, потом локально-адаптивный
  порог «темнее локального фона» + текстура (срастания не сегментируем).
- Панорамы — тайлами с перекрытием, бюджет ≤ 5 мин.
- Тальк калибруется по синим экспертным обводкам (цель по доле ±3%).

## Разделение работы (4 человека)

- **Классификатор** — `core/classifier.py`, `scripts/train.py`: обучение, подбор
  аугментаций/весов, довести macro-F1.
- **Сегментация талька** — `core/segment.py` + `notebooks/`: калибровка порога талька
  по синим обводкам, тайлинг панорам.
- **API/UI** — `api/main.py`, `app/main.py`: экспорт, batch, режим экспертной проверки.
- **Интеграция/демо** — `core/analyze.py`, `core/report.py`, Docker, отчёт, видео-демо.

Общие точки: контракт `analyze()` и `config.py` — менять согласованно.
